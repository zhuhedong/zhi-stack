# 真实任务试用协议与记录模板

本文件是待执行的试用方案，不是用户研究结果。当前没有受试者完成记录，也没有访谈、满意度或留存数据。自动化产生的测试资产不计作真实用户使用。

## 参与对象与安排

邀请 5–8 位经常同时处理技术资料、GitHub 项目与环境连接的开发者。每人使用独立试用工作台或自己的明确授权工作台。首次观察 30–45 分钟，三天后跟进一次。说明数据保存在其工作台，使用统计可关闭；参与者自行决定是否导出统计及反馈，不代其发送。

让参与者用自己的真实工作任务；若不方便提供资料，可用公开文章和无敏感数据的测试接口。主持人记录困难，避免直接告知操作位置。确实需要帮助时，记录帮助次数和原因。

## 首次任务

| 任务 | 完成证据 | 观察点 |
| --- | --- | --- |
| 连接服务或说明如何自行部署 | 能登录，或能准确找到部署入口与下一步 | 是否混淆桌面、服务端、PG 和两种密码 |
| 收录一篇实际会用的文章 | 正文可读；返回来源；图片可离线读取 | 等待预期、失败提示、后台任务是否可理解 |
| 把文章、仓库和一条测试连接归入同一项目 | 项目总览可打开三类资料 | “项目”是否贴合其组织方式 |
| 添加独立批注后同步文章，再回到旧版本 | 批注保留，历史可预览和恢复 | 是否担心覆盖、是否能找到回收站 |
| 离开条目后用关键词找回并打开 | 能定位目标，命中片段有帮助 | 搜索词、耗时、失败原因（不要导出敏感搜索原文） |
| 配置开发/预发 API 环境并查看历史 | 正确目标环境、变量替换、历史响应 | 是否误发到错误环境、是否理解重放使用旧值 |
| 订阅仓库并解释未读更新 | 能指出检查时间、结果和标记已读入口 | 检查失败后是否知道下一步 |
| 导出备份并在独立空实例恢复 | 数量、图片、附件与测试凭证一致 | 对备份范围、密码和恢复替换的理解 |

不要要求参与者为了试用连接真实生产服务或填写实际密码。API 调试任务使用其明确选择的测试端点。

## 三天后跟进

请参与者尝试回到首次项目，找出上次资料或笔记，继续一个实际任务。记录是否自主再次打开工作台、是否通过它找到资料、回到工作时缺了哪些上下文。能自主使用不等于长期留存，样本不足时只报告观察。

## 数据解释与导出

“使用与反馈”可导出 JSON。使用统计仅包含固定事件名、时间与不透明资产 ID，页面导出聚合结果，不含密码、文章正文、搜索词、请求参数或响应。反馈自由文本另外加密保存，导出前由参与者检查内容。

- **首次价值耗时**：记录中首次登录到首次新建或收录完成的时间。缺失起点、关闭统计或清理记录时不能补造。
- **资料复用**：最近 30 天同一资料打开至少两次。重复打开不自动证明有价值，应结合任务观察。
- **近期使用**：近 7 个 UTC 日期有实际事件的日期数。这是一个工作台的使用情况，不是 DAU 或用户留存率。
- **搜索和收录**：搜索是检索接口请求数，收录完成数是任务数；不等同于独立需求数或去重资产数。

汇总只写实际参与人数、各任务尝试与完成数量、帮助次数、可追溯的问题及反例。不要预填目标达成率，不把脚本验收、演示账号或主持人的操作算成参与者行为。达到多少完成率才扩大使用，应在试用前由产品负责人确定。
