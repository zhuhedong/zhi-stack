# 存储、部署与客户端连接复查

日期：2026-09-10。范围：现有文件存储实现、旧数据迁移、删除回收、Docker 配置及桌面端连接流程。以下区分本轮修复和仍需外部环境验收的项目。

## 已修复

| 问题                                          | 实际影响                                                 | 修复与验证                                                                                         |
| --------------------------------------------- | -------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 本地存储标识绑定绝对路径                      | 搬目录会误判，另一块空磁盘使用同样路径却可能被当成原存储 | 固定标识随文件目录备份；旧路径标识经逐文件校验后升级。搬目录和同路径换空卷测试通过                 |
| 文件清理受 5 秒总超时限制，并在删除请求里执行 | 慢 R2 删除反复中断，用户还要等待                         | 改为专用后台任务，保留持久队列。6 秒删除实际完成，HTTP 不等待；失败重启重试通过                    |
| 新库没有文件存储就绪检查                      | 错误权限也可显示服务已启动，首次上传才失败               | 每次启动执行小对象写入、读回校验和删除；空库存储失败拒绝就绪测试通过                               |
| 允许文件目录位于静态网页目录                  | 配置错误时可能绕过附件鉴权访问文件                       | 启动时拒绝该配置，独立集成检查通过                                                                 |
| 进程终止可能留下原子写入临时文件              | 原有队列只清理正式对象，临时文件会积累                   | 清理对应未引用对象的临时文件；中断文件回收测试通过。磁盘提交前增加显式刷盘                         |
| 默认 Compose 缺少桌面来源                     | 部分默认部署中桌面端被 CORS 阻止                         | 与独立远程 PG 配置统一，包含 Tauri 来源；配置检查通过                                              |
| Linux 只处理 Ctrl+C                           | Docker 的 SIGTERM 没有走应用优雅退出流程                 | 增加 SIGTERM 监听和 60 秒容器停止宽限。Windows 构建通过，Linux 信号分支尚未实跑                    |
| 桌面更换地址需要改源码/重新打包               | 用户无法自行切换实际部署的服务器                         | 登录页及顶部加入服务连接入口、地址保存、恢复默认和连接测试；8 项连接/组件测试通过                  |
| 切换连接可能复用旧密码或被旧请求影响          | 对错误服务继续提交密码，或旧 401 影响新会话              | 清除令牌和密码，忽略旧连接返回，校验 InfoHub 健康响应；连接测试不带认证或 Cookie，API 不跟随重定向 |

主要实现：[storage.rs](../server/src/storage.rs)、[files.rs](../server/src/files.rs)、[main.rs](../server/src/main.rs)、[server.ts](../src/lib/server.ts)、[ServerSettings.tsx](../src/components/ServerSettings.tsx)。

## 当前边界

- R2 使用带签名校验的本地 S3 协议服务验证，没有真实 Cloudflare Bucket 的联调凭据。
- 本机没有 Docker Engine，未实际运行 Linux 容器、SIGTERM 停机和远程 HTTPS 部署；配置解析及 Windows 构建不能代替这些检查。
- 已有外部文件在磁盘与 R2 之间或跨 Bucket 搬迁尚无工具，需要单独实施迁移；本地完整目录搬迁已经支持。
- 备份必须同时包含 PG 和文件存储。还没有一键备份/恢复任务或完整断电恢复演练。
- 单用户、单服务进程部署；会话没有分布式共享，当前不提供多实例高可用。
- 本轮没有重新完成所有原生窗口、安装包和浏览器业务操作的实机点击验收。
