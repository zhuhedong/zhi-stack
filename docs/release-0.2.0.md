# InfoHub 0.2.0

日期：2026-09-11。定位仍为个人单用户开发者工作台。本版围绕数据保护、项目整理、持续收录、API 工作区、安装维护及产品效果验证补全流程。

## 本版变化

| 问题 | 现在的行为 |
| --- | --- |
| 编辑、同步和删除后难以找回数据 | 更新前保留历史及旧图片；支持回滚、回收站和草稿恢复，凭证历史及草稿加密 |
| 备份、恢复和改密码依赖人工处理 | 完整加密备份、空实例/已有实例恢复、内容校验、主密码轮换和会话撤销；另有便携文章 ZIP |
| 项目只是一个字段 | 独立项目可编辑、归档、重命名，汇总三类资料；关联资产和文章采集来源可追溯 |
| 首次使用和维护步骤不清楚 | 区分连接与部署，实际进度引导，提供维护 CLI、升级/回退流程和发布质量检查 |
| 资料增加后难以整理和找回 | 相关度与命中片段、最近访问、常用资料、保存筛选、批量项目和标签整理 |
| 采集等待、失败和更新难管理 | 持久队列、阶段显示、重试、取消、重启恢复；仓库定时订阅、未读记录和阅读批注 |
| API 调试缺少工作上下文 | 加密环境及变量、请求/响应历史、按原请求重放、手动取消与迟到结果保护 |
| 缺少判断是否有用的依据 | 本工作台使用统计、关闭和清理开关、加密反馈及导出；真实任务试用协议与记录模板 |

## Windows 交付文件

`scripts/make-release.ps1` 要求当前源码有通过的验收报告，构建 release 服务端及 NSIS 安装器，生成 `release/infohub-0.2.0-windows-x64.zip`，目录内包含：

- `infohub_0.2.0_x64-setup.exe`：Windows x64 桌面安装程序。
- `infohub.exe`：独立桌面客户端。
- `server/infohub-server.exe`、`server/dist/`、配置示例和启动脚本：独立 HTTP 服务。
- `scripts/maintenance.mjs`、`scripts/release-ops.mjs`：备份、恢复及镜像升级维护工具。
- `operations.md`、`trial-protocol.md`、本文件和 `verification.json`。
- `manifest.json`：文件大小、SHA-256、源码摘要及验证边界。

客户端需要能连接到已配置 PostgreSQL 的 InfoHub 服务；安装客户端不等于部署服务。构建完成不等于安装、卸载或签名验证。现有 0.1 发布文件保留在原位置，新版使用独立目录。

## 升级与使用边界

0.1 升级前停止写入并成套备份数据库与文件，先在隔离副本演练。0.2 启动自动迁移；旧程序不能直接接回迁移后的数据库。回退需要恢复旧版完整快照。详细步骤见 `operations.md`，源码中的入口为 [运维手册](operations.md)。

备份采用生成时的主密码，改密码不会改变旧备份；机器配置、PG 账号和 R2 密钥另行保管。恢复至已有工作台需要当前身份及“恢复并替换”确认。当前部署按一个服务进程、多客户端实现。

自动识别/OpenAPI 收录任务加密，服务重启后等待解锁会话。仓库订阅记录更新提示，不自动覆盖笔记。API 历史会截断大响应，取消不能撤销目标端已执行的操作。统计默认启用但可关闭，不采集搜索词、密码、正文和请求参数。
